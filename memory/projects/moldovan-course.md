## Ключевые решения

- **Классические скрипты, не ES-модули.** Иначе `file://` ломается из-за CORS.
  Пользователь специально просил запускать через HTML-страницу.
- **Формат таблиц в `data.js` неоднороден**: строки бывают отдельными
  элементами `['tbl', head, row1, row2]` или одной вложенной группой
  `['tbl', head, [row1, row2]]`. Рендерер в `renderBlocks` различает оба
  варианта. Не «упрощать» одну из форм без правки рендерера.
- **Файлы озвучки ищутся по манифесту**, а не опросом файловой системы: опрос
  давал бы до 2 секунд ожидания на каждую фразу.
- **Транслитерация в имя файла** (`căsuță` → `casuta`) продублирована в
  `js/tts.js` (`slug`) и `tools/make-audio.ps1` (`Get-Slug`). Правки вносить
  в обоих местах.
- **Ответы сравниваются с нормализацией**: регистр, `ă/â→a`, `î→i`,
  `ș→s`, `ț→t`, лишние пробелы. Порог похожести 0.9.

## Ограничения среды

- В системе **нет румынского голоса** — только `Microsoft Irina` (ru-RU) и
  `Microsoft Zira` (en-US). Через `Speech_OneCore` — тоже только русские.
  Озвучка работает, но звучит русским голосом.
- Установка румынского голоса требует прав администратора:
  `dism /online /add-capability /capabilityname:Language.Speech~~~ro-RO~`.
  Не выполнять без явного согласия пользователя.
- Chrome на машине не установлен. Встроенный в инструменты Chromium
  показывает те же два русских голоса.
- `SpeechRecognition` требует Chrome/Edge на ПК + сеть + разрешение на микрофон.

## Грабли

- **PowerShell 5.1 читает `.ps1` без BOM как ANSI** — кириллица ломается, а
  битые кавычки роняют разбор скрипта. Все `.ps1` с не-ASCII держать в
  UTF-8 **с BOM**.
- В консоли Windows кодовая страница 866 — русский текст выводится мусором.
  В скриптах помогает `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.
- Браузерный инструмент не открывает `file://` — проверять только через
  локальный HTTP-сервер.
